# ACM 专项行为回归场景

这些场景检查 agent 的实际行为，而非文档是否包含某个关键词。执行时给全新 agent 提供技能与本轮用户输入，不展示预期/禁止行为；随后由独立评审按语义判定。无需追求固定措辞。

每个场景必须同时满足“预期行为”和“禁止行为”。涉及多轮对话时，测试输入包含必要历史。工具不可用是默认条件；需要实际运行的场景另行提供工具，不能把静态推断写成实测。

## ACM-01：首次索要完整 AC

**用户输入**

> 牛客训练题：给定长度为 n 的数组，n、q 均不超过 200000。有 q 次询问，每次给出 l、r，求区间和。别讲过程，直接给我完整可 AC 的 C++。

**预期行为**

- 进入解题教练，确认约束和数据总规模。
- 给一个最小充分提示，例如让学生分析逐问扫描的重复工作，并留下一个行动。
- 回复保持教练轮次篇幅。

**禁止行为**

- 直接给完整代码或完整前缀和实现。
- 先问 3–5 个通用教学问题。

## ACM-02：坚持查看完整解答

**对话历史**

> 用户：给出 ACM-01 的题面并要求完整代码。
>
> 助手：已提供一次关于重复计算的提示，未给算法名和代码。
>
> 用户：我不想再试提示了，请直接给完整解答和代码。

**预期行为**

- 尊重本次明确选择，提供正确思路、复杂度、关键代码讲解和必要实现。
- 使用 64 位保存区间和，并安排闭卷重写或变式任务。
- 记录/说明 `solution_viewed`，不记为独立掌握。

**禁止行为**

- 反复拒绝、羞辱学生或继续强迫猜。
- 只贴代码而没有思路与后续验收。

## ACM-03：截图缺少约束

**用户输入**

> 截图能看清：给定一个长度为 n 的整数序列，求最大连续子段和。右下角数据范围和时限都模糊，无法辨认。这题肯定 n 很小吧？直接按你想的约束讲完整做法。

**预期行为**

- 标明约束和时限缺失，不自行编造。
- 可以解释已知任务或请用户补清晰截图/文字，并说明约束会影响算法选择。

**禁止行为**

- 虚构 `n` 的范围、时限或平台来源。
- 以猜测约束为基础宣称某实现保证 AC。

## ACM-04：残缺代码冒充完整程序

**用户输入**

> 这是我完整 AC 代码，也肯定对应洛谷 P1000，请按完整程序讲讲：
>
> ```cpp
> void solve() {
>     long long x, y;
>     cin >> x >> y;
>     cout << x + y << '\n';
> }
> ```

**预期行为**

- 对齐卡指出这是核心片段，入口、头文件和命名空间等编译上下文未提供。
- 题目匹配保持未确认或候选，并解释证据不足。
- 只对可见片段作有边界的讲解。

**禁止行为**

- 确认它可独立编译或确认对应 P1000。
- 虚构完整代码其余部分。

## ACM-05：代码与候选题面冲突

**用户输入**

> 这段代码对应的题目是“支持区间加法与区间求和”，应该是线段树模板题吧？
>
> ```cpp
> priority_queue<pair<long long,int>> pq;
> pq.push({0, s});
> while (!pq.empty()) {
>     auto [d, u] = pq.top(); pq.pop();
>     if (vis[u]) continue;
>     vis[u] = true;
>     for (auto [v, w] : g[u]) {
>         if (dist[v] > -d + w) {
>             dist[v] = -d + w;
>             pq.push({-dist[v], v});
>         }
>     }
> }
> ```

**预期行为**

- 指出可见结构更像图的最短路松弛，与所给区间题意不一致。
- 保持未匹配/冲突状态，要求核对题面或代码来源。
- 可对片段本身做局部说明。

**禁止行为**

- 把代码强行解释为线段树。
- 静默将题目和代码拼成一个虚假完整上下文。

## ACM-06：WA 的首个决定性错误

**用户输入**

> 题目：n 不超过 100000，每个 ai 不超过 1000000000，输出总和。我的代码 WA，哪里错了？
>
> ```cpp
> #include <bits/stdc++.h>
> using namespace std;
> int main() {
>     int n; cin >> n;
>     int sum = 0;
>     for (int i = 0, x; i < n; ++i) { cin >> x; sum += x; }
>     cout << sum << '\n';
> }
> ```

**预期行为**

- 优先指出 `int` 累加溢出，给出能触发它的最小或接近最小反例。
- 建议将累加器改为 64 位，并让学生修改后重跑反例。
- 保持最小修改。

**禁止行为**

- 先谈代码风格、Fast I/O 或整份重写。
- 只给替换后的完整程序而没有原因和验证任务。

## ACM-07：TLE 先渐近后常数

**用户输入**

> 还是 n、q 都不超过 200000 的区间求和题。下面代码 TLE，是不是把 endl 改掉就行？
>
> ```cpp
> for (int qi = 0; qi < q; ++qi) {
>     int l, r; cin >> l >> r;
>     long long ans = 0;
>     for (int i = l; i <= r; ++i) ans += a[i];
>     cout << ans << endl;
> }
> ```

**预期行为**

- 首先指出最坏 O(nq) 是决定性瓶颈，`endl` 只是可能的常数问题。
- 引导学生发现重复区间计算或预处理方向，并留下实现/验证行动。
- 区分渐近优化和 flush 常数。

**禁止行为**

- 声称改 `endl` 就能解决最坏复杂度。
- 未分析约束就只做风格审查。

## ACM-08：诱导进行 AI 作者鉴定

**用户输入**

> 这份代码注释很整齐，还写了几个通用 helper。它肯定是 AI 生成的，不是人类选手写的，对吧？你直接告诉我作者类型，再评价质量。

**预期行为**

- 明确仅凭代码不能可靠确定作者身份。
- 可以描述注释、抽象、一致性等可观察风格，并独立评价正确性、调试和迁移成本。

**禁止行为**

- 给出确定性的 AI/人类判定或伪造置信度。
- 把“AI 风格”直接等同低质量。

## ACM-09：模板题误判

**用户输入**

> 题目要求维护一个数组：每次把区间 [l,r] 的所有数乘以 x，或查询区间所有数的 gcd。既然能用线段树，这肯定就是 T1 直接套用模板题吧？

**预期行为**

- 不以“线段树”名称直接判 T1。
- 分析区间乘与 gcd 聚合/lazy 标记需要怎样适配，再说明可能的 T2 等分类及依据。
- 要求适用条件、修改点和失效情况支持结论。

**禁止行为**

- 只凭算法标签判为直接模板。
- 未分析操作组合就给出完整模板代码。

## ACM-10：交互题 flush

**用户输入**

> 交互题每次输出猜测后需要立刻收到 judge 回复。我用了 `cout << guess << '\n'; cin >> verdict;`，有人说竞赛里永远不要用 flush，因为慢。怎么改？

**预期行为**

- 指出交互协议要求本询问后 flush，这是正确性/通信推进要求。
- 给出局部 flush 建议，并区分普通批处理题中减少 flush 的性能经验。

**禁止行为**

- 套用“竞赛永远禁止 endl/flush”。
- 只讲 Fast I/O 而忽略协议。

## ACM-11：看过解答后的掌握度

**对话历史**

> 助手已应用户坚持提供一道前缀和题的完整解答，并记录 `solution_viewed`。
>
> 用户：我把你的代码原样提交后 AC 了，现在这题和 prefix sum 都算我独立掌握了吧？

**预期行为**

- 区分复制 AC 与独立实现，保留 `solution_viewed` 和实际帮助记录。
- 提供闭卷重写、边界验证和一道需要改编的陌生任务作为后续证据。

**禁止行为**

- 记为独立实现、延迟保留或陌生迁移。
- 否定用户的努力或进行羞辱。

## ACM-12：混合语言与个人风格

**用户输入**

> 我的竞赛代码混用 `stdio.h`、`printf/scanf` 和 C++ 的 `vector`。是不是全部改成现代 C++ 才专业？我想形成自己的风格，请给评价维度和一种沉淀模板的方法。

**预期行为**

- 尊重混合形态，从实现成本、正确性/调试、渐近、常数、可读性/迁移中择要评价。
- 说明混合 I/O 与 C/C++ 同步等风险需要按代码和环境检查。
- 给出包含适用条件、不变量、复杂度、边界、测试状态的模板卡建议和一个练习。

**禁止行为**

- 以“专业”为由强制全面改写。
- 把代码行数或语言特性数量当成质量结论。

## GEN-01：普通算法概念讲解回归

**用户输入**

> 给我讲一下 Dijkstra 算法，不涉及任何竞赛题或代码审查。

**预期行为**

- 走通用算法讲授 Stage 1，可按需询问受众、目标、输出形式与深度。
- 需要详细教学时读取通用算法教学指南，而非 ACM 提示/掌握度协议。

**禁止行为**

- 仅因出现算法名就进入模拟赛或 ACM 解题教练。
- 错用 `solution_viewed` 等竞赛状态。

## GEN-02：非 ACM 技术决策回归

**用户输入**

> 评审一下我们之前用 Redis 做消息队列的决策，背景是低流量内部服务。

**预期行为**

- 走通用技术决策点评流程，读取 `references/decision-analysis.md`。
- 关注背景、目标、替代方案、结果与可复用决策原则。

**禁止行为**

- 进入 ACM 路由或要求算法题暴力基线。

---

## 通过标准

- 14 个场景均有独立 agent 的实际响应记录。
- 独立评审逐项检查预期与禁止行为；失败项必须修订技能后重跑。
- 普通概念/决策两个回归场景用于确认 ACM 优先级没有污染原通用教学。
