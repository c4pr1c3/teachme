> 以下按常见题意处理：数组下标从 1 开始，每次询问闭区间 `[l,r]` 的元素和；输入依次为 `n q`、数组元素、`q` 组 `l r`。若原题格式或值域不同，需要相应调整。

### 思路与正确性

定义 `pre[i]=a[1]+...+a[i]`，且 `pre[0]=0`。于是 `sum(l,r)=pre[r]-pre[l-1]`：两式相减恰好消去第 1 到第 `l-1` 项，只留下目标区间。数组不修改，所以只需预处理一次。

### 复杂度

- 预处理：`O(n)`
- 所有询问：`O(q)`
- 总时间：`O(n+q)`；空间：`O(n)`

### C++17 完整代码

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, q;
    if (!(cin >> n >> q)) return 0;
    vector<long long> pre(n + 1, 0);
    for (int i = 1; i <= n; ++i) {
        long long x;
        cin >> x;
        pre[i] = pre[i - 1] + x;
    }
    while (q--) {
        int l, r;
        cin >> l >> r;
        cout << pre[r] - pre[l - 1] << '\n';
    }
    return 0;
}
```

关键点：`pre[0]=0` 统一处理 `l=1`；使用 `long long` 保存前缀和及答案；数组元素为负数时公式仍成立。当前验证状态：**静态审查完成，未实际编译运行**。

### 评价自己风格的五个维度

| 维度 | 结合当前写法，重点检查什么 |
|---|---|
| 实现成本 | 熟悉的 `scanf/printf` 如果写得快且稳定，就有价值；`vector` 能减少手动管理动态内存的成本。 |

| 常数性能 | 关注 I/O 次数、不必要 flush、容器分配和拷贝；未实测时不断言某种 I/O 一定更快。 |
