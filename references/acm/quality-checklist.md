# ACM 输出质量检查清单

在发送教练提示、调试结论、完整审查或完整解答前，按当前分支检查相关项目。无需把检查过程展示给学生。

## 路由与教学

- [ ] 已选择正确模式；ACM 场景没有落入通用 3–5 问或长讲义流程。
- [ ] 本轮只推进一个主要认知障碍，并留下一个学生行动。
- [ ] 提示对应当前 milestone，级别没有超过学生所需。
- [ ] L1/L2 没有意外泄露算法名、完整状态设计或实现骨架。
- [ ] 缺前置时补了必要知识，而不是强迫学生猜。
- [ ] 首次索要 AC 时先提供教练路径；坚持查看后的完整解答包含依据、讲解和闭卷任务。
- [ ] 模拟赛中没有提供具体题目的提示、答案或代写。

## 上下文与代码审查

- [ ] 代码完整度、语言形态、题目匹配状态和验证状态准确。
- [ ] 候选匹配有证据，未匹配时没有虚构考点、约束或题目来源。
- [ ] 先理解学生代码意图，再指出问题；首个决定性错误优先。
- [ ] WA/TLE/RE/MLE 的结论有对应推理、反例或实测证据。
- [ ] 渐近复杂度包含测试组与隐藏操作，常数建议没有替代错误的算法复杂度分析。
- [ ] 默认给最小修改建议；整份重写来自明确请求。

## 风格、优化与模板

- [ ] 风格评价引用具体代码，并覆盖实现、正确性、渐近、常数或迁移中的相关维度。
- [ ] 没有把短代码、短变量、语言选择或“AI 感”直接等同于质量。
- [ ] 没有仅凭代码确定 AI/人类作者身份。
- [ ] 性能主张区分静态推断与 benchmark，交互题 flush 按协议处理。
- [ ] 模板题 T1–T4 判定有约束、瓶颈、适用依据、修改点和失效反例。
- [ ] 个人模板卡包含适用条件、不变量、复杂度、陷阱和测试状态。

## 验证与学习证据

- [ ] 准确区分用户声明 AC、样例、静态审查、本地运行、边界、对拍和性能实测。
- [ ] 没有把样例或对拍通过外推为无条件正确证明。
- [ ] 已记录本轮最高帮助级别和 `solution_viewed` 状态；提供完整解答时，可见回复中显式标注 `solution_viewed=true`、L5 及“不计为独立实现”。
- [ ] 跟写、复制 AC、旧题重做和陌生迁移没有混为同一种掌握证据。
- [ ] 未获授权时不写长期档案；获授权时只写训练工作目录的 `.teachme/acm/`。

## 泄题与篇幅终检

- [ ] 教练回复中没有意外出现完整可编译解答或超出当前级别的完整伪代码。
- [ ] 局部代码片段只服务当前语法/调试问题，没有拼起来替代学生整题实现。
- [ ] 输出长度适合当前模式：教练轮次短，完整审查和明确请求的讲解才展开。
- [ ] 最终状态包含一个可观察的下一步，而不是“理解一下”“再优化一下”等空泛建议。
